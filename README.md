# 오늘의 발표자 — AI 얼굴 인식 학생 추첨 웹앱

전자칠판 카메라(또는 외장 웹캠)로 교실을 비추면 학생 얼굴을 실시간으로 인식하고,
지정한 인원만큼 무작위로 발표자를 뽑아주는 웹앱입니다. 서버 없이 브라우저에서만 동작하며,
GitHub Pages로 바로 배포할 수 있습니다.

## 1. 주요 기능 및 교실 30명 강제 인식 시스템

| 기능 | 설명 |
|---|---|
| **AI 멀티 타일 확대 스캔** | 교실 원거리/뒷자리 학생의 작은 얼굴이 모델 축소 과정에서 소실되지 않도록, 전체 프레임 스캔과 3개 분할 타일 크롭 확대를 병행해 작은 얼굴 인식률을 극대화 (IoU NMS 중복 병합) |
| **화면 터치/클릭 강제 등록** | 전자칠판 터치스크린 지원! AI가 놓친 학생이 있더라도 화면 속 학생 자리를 직접 터치하면 즉시 얼굴 박스(강제 등록)가 추가되며, 다시 터치 시 삭제 가능 |
| **➕ 30명 자동 채우기** | 현재 AI가 인식한 학생들을 그대로 유지하면서, 미인식된 빈자리를 교실 책상 배열 그리드로 자동 계산해 정확히 30명을 순식간에 완성 |
| **🏫 30명 좌석 일괄 배치** | 교실 5행×6열 책상 배열로 30개 자리를 원근감(앞자리 확대, 뒷자리 축소)을 반영해 한 번에 생성 |
| **📌 위치 고정 (잠금)** | 학생들이 고개를 숙이거나 움직여도 추첨 박스와 번호가 사라지거나 흔들리지 않도록 자리를 완벽 고정 |
| **↔️ 좌우 반전 토글** | 전자칠판 전면 카메라 사용 시 실제 교실 좌석 방향과 화면의 좌우를 일치시킬 수 있는 미러 모드 전환 |
| **⚡ 초고감도 교실 모드** | 다인원·원거리 학생 인식을 위해 신뢰도 임계치를 최적화(0.18)하여 측면 응시나 마스크 착용 학생도 인식 |
| 얼굴별 고유 번호 표시 | 인식된 각 얼굴 위에 고유 번호 배지를 표시하며, 미러링 여부에 맞춰 숫자가 항상 정방향으로 렌더링 |
| 인원 지정 룰렛 추첨 | 인식 및 등록된 학생 수 내에서 원하는 인원(1~N명)을 지정하고 공정한 난수(crypto)로 추첨 |
| 당첨자 식별 (정지화면 + 썸네일) | 추첨 완료 시 화면이 정지되어 당첨자의 금색 박스가 교실 화면 위에 남고, 잘라낸 얼굴 썸네일과 번호가 하단에 표시 |
- 컨트롤 패널의 **해상도 모드**를 환경에 맞게 선택 (카메라·PC가 지원하는 실제 해상도는
  브라우저가 자동으로 가장 가까운 값을 맞춰주며, 화면 상단 상태 표시줄에 실측 해상도가 나타남)

  | 모드 | 요청 해상도 | 적합한 상황 |
  |---|---|---|
  | 근거리 · 720p | 1280×720 | 좁은 교실, 저사양 PC, 카메라가 학생과 가까울 때 (반응 속도 우선) |
  | 표준 · 1080p (기본값) | 1920×1080 | 일반적인 교실 30명 내외, 대부분의 상황에 권장 |
  | 원거리 고화질 · 1440p | 2560×1440 | 넓은 교실, 카메라~뒷자리 거리가 먼 경우 |
  | 최대 화질 · 4K | 3840×2160 | 초광각 카메라 + 고사양 PC 전용, 가장 먼 거리까지 화질 확보하지만 지연이 늘 수 있음 |

- 카메라를 교실 중앙 앞쪽에 배치해 뒷자리와의 거리를 최대한 좁힐 것
- 역광을 피하고 조명을 밝게 유지할 것
- 해상도를 높였는데도 PC가 버벅인다면 한 단계 낮은 모드로 내려서 반응 속도를 우선할 것
- 그래도 인식이 불안정하면 **번호 추첨 모드**를 대체 수단으로 사용

**화면이 어둡고 흐리게 보일 때**
가장 흔한 원인은 카메라가 창문이나 조명을 등지고 촬영해 역광이 생기는 경우입니다.
브라우저는 카메라의 실제 노출(exposure)을 세밀하게 제어하기 어려워서, 이 앱은 화면에
밝기/대비 보정 필터를 입혀 어둡게 나온 영상을 밝혀주는 **밝기 보정 슬라이더**를 제공합니다.
그래도 개선이 부족하면:
- 카메라(특히 스마트폰)를 창문 등 광원을 등지지 않는 방향으로 옮겨주세요.
- 스마트폰을 카메라로 쓴다면 전면(셀피) 카메라보다 후면 카메라 화질이 더 좋은 경우가 많습니다.
- 교실 조명을 최대한 밝게 켜주세요.

## 2. 파일 구조

```
student-picker/
├── index.html   # 화면 구조 (카메라 모드 / 번호 추첨 모드 두 탭)
├── style.css    # 디자인 (다크 스테이지 + 시안/골드 액센트, 조리개 셔터 인트로)
├── app.js       # 얼굴 인식, 트래킹, 추첨 로직, 컨페티 (ES 모듈)
└── README.md    # 이 문서
```

별도의 백엔드나 데이터베이스는 사용하지 않습니다. 모든 처리는 브라우저에서 이루어지며,
MediaPipe 모델 파일은 Google이 호스팅하는 CDN에서 최초 실행 시 자동으로 내려받습니다
(인터넷 연결 필요, 이후 브라우저 캐시로 재사용).

## 3. 전체 코드

`index.html`, `style.css`, `app.js` 세 파일이 이 대화의 첨부 파일로 함께 제공됩니다.
세 파일을 같은 폴더에 두면 바로 동작합니다.

## 4. 배포 방법 (GitHub Pages)

1. GitHub에서 새 저장소를 만듭니다 (예: `student-picker`). Public으로 설정합니다.
2. 저장소에 `index.html`, `style.css`, `app.js` 세 파일을 업로드합니다.
   (저장소 메인 페이지 → **Add file → Upload files** 로 세 파일을 한 번에 드래그해도 됩니다.)
3. 저장소 상단 **Settings → Pages** 로 이동합니다.
4. **Build and deployment → Source** 에서 `Deploy from a branch` 를 선택합니다.
5. **Branch** 를 `main` (또는 기본 브랜치), 폴더는 `/ (root)` 로 선택 후 **Save** 를 누릅니다.
6. 1~2분 후 같은 화면 상단에 `https://<사용자아이디>.github.io/student-picker/` 형태의 주소가 표시됩니다.
   이 주소를 전자칠판 브라우저에서 열면 됩니다.
7. 접속 시 브라우저가 카메라 권한을 물으면 **허용**을 눌러야 합니다.
   (GitHub Pages는 기본적으로 HTTPS이므로 카메라 API가 정상 동작합니다.)

### 참고: 코드를 수정하고 싶을 때
파일을 로컬에서 수정한 뒤 같은 방법으로 다시 업로드(또는 git push)하면
GitHub Pages가 자동으로 새 버전을 반영합니다. 별도의 빌드 과정이 없습니다.

## 5. 개인정보 관련 안내

이 앱은 얼굴 이미지나 인식 결과를 서버로 전송하거나 저장하지 않습니다.
모든 얼굴 인식은 사용자의 브라우저 안에서만 실시간으로 처리되고, 화면을 벗어나는 순간 사라집니다.
다만 학생 얼굴이 화면에 표시되는 특성상, 학교의 초상권/개인정보 관련 지침에 따라
사전 안내 또는 동의 절차를 거치는 것을 권장합니다.
